# 向栈桥投稿

栈桥的文章以 **Markdown 文件 + Git 提交** 的形式维护：文章源码在仓库里，
提交 Pull Request 通过审核后合并，会自动同步到站点。

## 怎么写一篇文章

1. Fork 本仓库，新建分支
2. 复制 `content/posts/_template.md`，放到 `content/posts/` 下，文件名用小写英文和连字符，例如 `my-first-agent.md`
3. 填写 frontmatter 并写正文，然后提交 Pull Request
4. 审核通过合并后，文章会在几分钟内出现在 `/blog`

## frontmatter 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 文章标题，80 字以内 |
| `slug` | ✅ | 网址标识，小写英文与连字符，建议与文件名一致 |
| `summary` | ✅ | 摘要，60-140 字，列表页与搜索会用到 |
| `author` | ✅ | 你的栈桥用户名，会自动关联到账号；没账号可以先注册一个 |
| `date` | ✅ | 发布日期，格式 `2026-01-01` |
| `tags` | ❌ | 标签数组，最多 8 个 |
| `projects` | ❌ | 关联的项目 slug 数组，可以写多个；项目详情页会显示这些文章 |
| `cover` | ❌ | 封面图地址，不填会自动生成一张占位封面 |
| `draft` | ❌ | 写 `true` 时不会公开显示，适合先合并再慢慢写完 |

## 写作约定

- 正文用 Markdown，代码块请标注语言（```ts / ```python），方便高亮
- 涉及成本、收入、用户量这类数字时，请写清楚口径与时间范围，我们会在页面上标注「数据由作者提供」
- 不要写纯广告；产品介绍可以，但要讲清楚解决了什么问题、哪些地方还不完善
- 图片建议放在 `public/uploads/` 下并在正文中引用绝对路径；后续会支持对象存储

## 一篇文章可以关联多个项目

项目与文章是多对多关系：一篇文章可以同时讲两个项目（比如「我用两个模型拼了个工具」），
一个项目也可以有多篇文章（发布、复盘、性能优化）。关联后：

- 项目详情页会出现「相关文章」
- 文章页会显示「涉及的项目」卡片

## 本地预览

```bash
npm install
npm run db:setup      # 建库 + 示例数据
npm run dev           # 启动后打开 http://localhost:3000/blog
```

开发服务器会监听 `content/posts/` 目录，保存 Markdown 即自动同步到数据库，不需要重启。
如果文章没出现，检查两件事：`slug` 是否重复、`projects` 里写的项目 slug 是否存在
（同步脚本会在控制台打印找不到的项目）。
