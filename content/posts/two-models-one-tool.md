## 两种「不用 API」

很多人把「本地推理」当成一种方案，其实它至少有两种完全不同的形态。

**第一种：把模型搬到用户设备上。** 掌上机器学习走的就是这条路，模型量化成 WebAssembly，
推理在浏览器完成。服务器只负责发文件，用户越多，成本越不涨。

**第二种：把模型留在自己的机器上。** 画钟是在租来的 GPU 上跑 SDXL，
用户请求打到我的服务器，再由服务器调用本地模型。

## 成本结构对比

| | 掌上机器学习 | 画钟 |
| --- | --- | --- |
| 算力成本 | 0（用用户的设备） | 1400 元/月（GPU 租用） |
| 服务器成本 | 80 元/月 | 100 元/月 |
| 随使用量增长 | 几乎不增长 | 明显增长 |
| 首屏体验 | 需要下载 4MB 模型 | 立即出图 |

差别在于**成本承担者**：前者把算力成本转移给了用户，代价是首次加载和低端设备上的卡顿；
后者体验一致，但每一张图都在烧我的钱。

## 什么场景该选哪个

- 模型小于 10MB、对延迟不敏感、用户设备不差 → 放到端上
- 模型需要 GPU、要保证出图质量、用户设备参差不齐 → 留在自己这边
- 两者都不满足 → 老老实实调 API，别为了省钱把体验做坏

## 一个反直觉的结论

画钟的 GPU 一个月 1400 元看着很贵，但因为卡不会闲着，单张图的成本只有 0.25 元，
比按张付费便宜一个数量级。**前提是你能把卡用满**——如果一天只出十张图，
本地部署反而比调 API 贵二十倍。

所以决定之前先算一件事：这台机器一天有多少个小时在干活？
