# 特价电影票 · 微信小程序

一个**可直接运行**的微信电影购票小程序，原生开发（无 npm、无云开发依赖），
导入微信开发者工具即可编译预览。

> **当前定位：前端演示版（Frontend Demo）**
> 全部数据来自本地模拟数据源，订单存在本地 Storage，支付为界面模拟。
> 它完整演示了购票的产品流程与页面交互，但**不具备线上售卖能力**，
> 也不满足微信小程序提审上线的要求。详见下方「功能完成度」。

**核心链路与业务逻辑**

- ✅ **完整购票链路**：首页/详情 → 选择场次 → 选座 → 确认订单 → 模拟支付 → 订单详情
- ✅ **订单状态机**：`待付款 → 出票中 →（5 秒后自动）已出票 → 退款/售后`，
  状态推进用**时间戳比对**而非页面定时器，退出页面再进来也不会卡在「出票中」
- ✅ **本地持久化**：订单写入 `wx.setStorageSync('mt_orders')`，卸载小程序后仍在；
  城市、登录态、搜索历史同样本地持久化
- ✅ **确定性模拟数据**：用 `util.rngFrom(seed)`（mulberry32 + FNV-1a）生成排片与座位图，
  **同一入参永远得到同一结果**，反复进出选座页座位图不会变化
- ✅ **场次停售判断**：仅「今天」且开场时间 ≤ 当前时间 + 5 分钟的场次标记为停止售票，
  明天/后天的场次永不停售；停售场次整行置灰且点击拦截
- ✅ **响应式适配**：座位尺寸按列数动态计算（可用宽度 600rpx，钳制 38~56rpx），
  不同列数下均不溢出

**工程化与质量保障**

- ✅ **静态自检** `tools/check_project.py`：JSON 可解析、JS 语法（`node --check`）、
  WXML 标签闭合与属性重复、13 个页面四件套齐全、tabBar 图标存在、

## 四、主要模块说明

### `utils/mock.js` —— 数据源（接后端的唯一替换点）

导出 9 个方法，页面层只依赖这些方法签名：

| 方法 | 用途 |
| --- | --- |
| `getMovies(status)` | 按「正在热映 / 即将上映」取影片列表 |
| `getMovieById(id)` | 取单部影片详情 |
| `getCinemas()` / `getCinemaById(id)` | 影院列表 / 单个影院（含经纬度） |
| `getShowDates()` | 生成今天/明天/后天三个日期项 |
| `getShowtimes(cinemaId, movieId, dayIndex)` | 场次列表，含价格、折扣、影厅、**停售状态** |
| `getSeatMap(cinemaId, movieId, showtimeId)` | 座位图（行列、过道、已售座位） |
| `getCinemaMovies(cinemaId)` | 某影院当日有排片的影片（供影院选片页轮播） |
| `search(word)` | 影片 / 影院双通道搜索 |

**替换为真实后端时，只需重写这一个文件的导出方法，页面层零改动。**

### `utils/store.js` —— 本地存储层

- 统一封装 storage key：订单 `mt_orders`、城市 `mt_city`、用户 `mt_user`
- 提供订单 CRUD 与按状态筛选、数量统计
- 定义四态订单常量与配色
- `advanceTicketingOrders()`：**出票状态推进**——在页面 `onShow` 时比对时间戳，
  把到点的「出票中」订单翻成「已出票」，避免依赖页面级定时器

### `pages/seat` —— 选座（逻辑最重的页面）

- 座位尺寸随列数动态计算，保证不溢出
- 过道位置由数据驱动，渲染时插入间隔
- 三态座位：可选 / 已选 / 已售，已售座位来自确定性随机
- 每单限选 4 座，超出提示
- 底部实时汇总已选座位与总价

### `pages/cinema-detail` —— 影院选片页

- 海报用 `<swiper previous-margin next-margin>` 实现当前项居中、左右露出相邻海报
- 非当前海报 `scale(0.94)` 缩小，当前项 `scale(1)`
- 场次横向行承载「时间 / 语种制式 / 影厅 / 价格 / 折扣 / 原价 / 购票 / 停售提示」
- 停售场次整行置灰且拦截点击

## 五、开发约定

- **WXSS 不使用 CSS 变量**（`var()` 在部分基础库支持不稳定），颜色统一写字面量
- **WXML 插值 `{{}}` 内禁止函数调用**（如 `.toFixed()`），所有展示文案在 JS 层算好。
  余票、想看人数、金额、日期标签均由页面 JS 预处理
- 金额一律以「元」为单位存储，展示时用 `util.money()` 保留两位小数
- 模拟数据必须**确定性**，用 `util.rngFrom(seed)`，同一入参永远同一结果
- 图标用**程序化生成**而非手绘，保证多端配色一致
- 视觉装饰（如箭头）优先用 CSS 绘制而非 emoji——emoji 多端配色不可控
