这三个目录在官方仓库里，当前工程**没有**拷进来（只拷了 `room/atomic_x/chat`），需要时执行

## P3 · 工程化与分发（内部 App 也得有）

| 事项 | 说明 |
| --- | --- |
| 内部分发渠道 | 蒲公英 / Firebase App Distribution / 企业微信应用；配上版本更新检查接口 `GET /api/v1/app/latest` |
| CI 打 APK | GitHub Actions 或 GitLab CI：`./gradlew assembleRelease` + 上传产物 |
| 崩溃上报 | Bugly（腾讯系）或 Firebase Crashlytics |
| release 混淆验证 | `isMinifyEnabled = true` 后跑一遍，确认腾讯 keep 规则够用（现在关着） |
| 后端加硬化 | JSON 文件 → SQLite/Postgres；加限流、UserSig 缓存；套 HTTPS 证书 |
| 网络安全配置 | 现在全放 cleartext，改成只放行公司内网域名 |
| 测试 | Repository 层用 MockWebServer；UserSig 算法与腾讯官方示例对拍（当前只验证了「能生成」） |

## P4 · 体验打磨

- 深色模式（房间页已是深色，其余页面跟着 `MaterialTheme`，需要逐页看一遍）
- 无障碍：`contentDescription` 补齐、TalkBack 走一遍、大字号不溢出
- 平板/折叠屏：会议页已支持横屏，可做列表双栏
- 弱网提示与断线重连提示（TRTC 有网络质量回调）
- 首次使用引导：权限用途说明、房间号怎么分享

---

## 建议顺序

```
P0（编译+联调） → P1 里的「密码 + 邀请 + 聊天」→ P2 的 AI 纪要 → P3 分发与 CI
```

理由：先把「能稳定开一场会」坐实，再堆功能；AI 纪要和 1v1 呼叫这类是加分项，不影响主线能不能用。
